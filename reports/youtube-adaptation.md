# YouTube 直播适配实施与验证

验证日期：2026-10-17～18（北京时间），更新至本轮工作区全面复查。实现已落在当前工作区，尚未发布安装包。此前“全部完成”的表述不成立：真实下载器、聊天请求和 ExFAT 快照均存在遗漏，本轮已复现并修复。发布验收仍未全部完成。

## 功能与复用

YouTube 接入现有平台适配器、调度器和录制引擎接口，复用直播间管理、自动/手动录制、状态通知、直播墙、弹幕存储/回放/导出、标记、精彩片段、历史记录、后处理及上传流程。没有另建业务管理系统。

- 支持频道、`@handle`、视频、短链接及直播链接。频道解析为稳定 channelId，指定视频与频道分别作为监控目标。
- 频道默认每 120 秒检测一次；没有启用的 YouTube 房间时不新增轮询定时器。同时直播时保持已选场次，否则选择最早的直播。录制重连锁定 videoId，避免切到另一场。
- 从当前直播位置开始录制。原画保留源视频/音频编码，使用 MKV 容器；不为保存录像额外编码。分辨率取实际媒体信息。
- 下载器先无损输出延迟初始化的分片 MP4，待 AAC 配置就绪，再由本地 FFmpeg 无损封装为 MKV；中转不落额外视频文件。直接向管道写 MKV 会在 YouTube HLS AAC 缺少初始化配置时失败，这是本轮真实直播复现的零字节录像根因。

该容器限制也可从 [FFmpeg Matroska 封装器源码](https://github.com/FFmpeg/FFmpeg/blob/master/libavformat/matroskaenc.c) 的 `get_aac_sample_rates` 确认：缺少初始化信息且输出不可寻址时拒绝写入。AAC 配置处理参见 [FFmpeg 官方位流过滤器文档](https://www.ffmpeg.org/ffmpeg-bitstream-filters.html#aac_005fadtstoasc)。

- 断线后记录独立分段，复用录制缓冲和恢复流程，结束时通过 FFmpeg 无损合并。失败保留原始分段，阻止后处理或上传不完整主文件，支持随后重试。
- 复用现有 FLV 播放组件，按观看需求生成兼容流。H.264/AAC 可直接封装，其余编码仅转换播放副本；原始录像保留。回看、定位和片段导出使用源文件快照。
- 聊天通过 youtubei.js 接入现有采集与存储接口，包含文本、付费聊天和会员消息，使用有界去重与待写队列。
- 公开直播可匿名访问。设置页支持导入 Netscape 格式 Cookie，复用系统钥匙串；配置导出与 API 响应不回传凭据。临时凭据文件限制权限并在进程结束后删除。
- 使用环境变量和操作系统静态 HTTP/HTTPS 代理设置。没有新增应用内代理选项。PAC/SOCKS 需另行提供可用 HTTP 代理或全局网络。

数据库通过第 56 次迁移扩展平台并保存频道映射，保留已有房间、索引与关系。旧平台继续走原有录制路径；YouTube 的媒体、网络和聊天能力按需加载。

## 性能与数据保护

| 环节 | 限制或策略 |
| --- | --- |
| 元信息解析 | 2 个并发、16 个排队、30 秒超时；128 项短期缓存和请求去重 |
| MKV 解析 | 增长缓冲复用；最大 16 MiB，媒体头最大 1 MiB |
| 实时预览 | 无观看者时不启动编码器；最高 1080p/30fps，硬件优先、软件 2 线程 |
| 预览背压 | 待发 4 MiB、编码输入 8 MiB；慢预览独立终止，不阻塞录像落盘 |
| 历史兼容播放 | 最多 4 路，首字节超时 15 秒，断开时回收进程 |
| 分段整理 | 同一文件任务去重，最多 2 路执行、32 项在途任务 |
| 文件与进程 | 原子保留录像名，防止频道/视频同时录制造成覆盖；复用进程注册与退出回收 |

媒体快照优先使用同卷硬链接；macOS/Linux 上不支持硬链接时，使用继承的只读文件句柄维持源文件身份，不复制整段录像。已在用户实际 ORICO ExFAT 卷验证改名/删除后读取、历史兼容回放和片段导出。Windows 上不支持硬链接的卷仍会明确提示使用 NTFS，该情况尚未适配。

解析器微基准处理 356.8 MiB 模拟 720p 数据（200 次、64 KiB 输入块），一次测量为 91.5 ms 墙钟时间、143.457 ms CPU、3898.3 MiB/s；保留 Buffer 约 1.9 MiB。运行方式：

```sh
npm --prefix backend run build
node --expose-gc backend/scripts/youtube-media-benchmark.mjs
```

该结果仅衡量解析器，不代表网络下载、播放转码或两小时整链路负载，也不构成零性能回归保证。

## 依赖与运行

- yt-dlp 固定为 `2026.08.19`，下载时验证固定 SHA-256。
- youtubei.js `18.1.0`、undici `6.29.1`；FFmpeg/FFprobe 使用固定版本安装器提供打包资源。

源码环境先执行 `npm run youtube:setup`，也可设置 `LR_YTDLP_PATH`。正常桌面打包自动准备并包含上述资源，不要求用户额外安装命令行工具。

### 再次黑屏排查（19:43 起）

用户再次报告浏览器可观看、应用预览黑屏。本轮找到并修复两处前端遗漏：

- `useVideoPlayback` 原本对所有平台统一使用 12 秒无帧超时。YouTube 还需要解析格式、启动下载器及封装，尚未出画便被前端主动销毁，最后一个观看者断开又会取消后端取流。当前实例此前多次出现 `STREAM_ENDED_BEFORE_DATA`。现将 YouTube 每次首次出画等待上限设为 90 秒，后台仍保留自身启动超时；开始播放后继续使用原有 12 秒停滞恢复。其他平台超时不变。
- 预览弹窗等待源尺寸时隐藏整个播放器，加载和错误提示也继承了隐藏状态。现仅隐藏视频内容，显示加载与错误反馈，保留原有竖屏尺寸过渡。

修复后使用原链接 `UWXyKZl3e_A` 在当前开发后端与前端实测：前两次关闭后重新打开分别在 36.310 秒、27.928 秒产生预览数据，均显示 1920×1080、`readyState=4`，播放时间分别推进至 25.23 秒和 57.12 秒。这些启动时间均超过旧的 12 秒限制。加载文字的实际 CSS 可见性为 `visible`，截图见 [加载反馈](youtube-preview-loading-fixed.png) 与 [实际播放](youtube-preview-black-screen-fixed.png)。第三次重新打开在 29.271 秒产生数据，同样显示 1080p、`readyState=4`，播放时间推进至 16.01 秒。三轮后端启动诊断保存在 [诊断记录](youtube-preview-black-screen-diagnostics.json)。本轮验证使用本地开发页面，不能替代原生 WebView 和安装包验收。

新增 4 项定时器回归，覆盖普通预览/缩略预览等待、启动总超时、出画后停滞恢复以及旧平台原有超时；前端全量 81 文件、572 项通过，构建通过，lint 无错误（保留既有警告）。本轮不改动后端录像、调度和写盘路径。
