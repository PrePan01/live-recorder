## 0. 通用约定

- 环境注入：`FakeClock` 控制超时/重试，禁止真实等待；进程/端口/ready 文件/实例锁由测试替身注入或由安装包真机验证。
- 单实例锁 `instance.lock` 原子保存 `{instanceId,pid,version,startedAt}`；ready 文件为 `AppInstance{instanceId,pid,host,port,baseUrl,apiVersion,startedAt}`，两者均「临时文件 + 原子 rename」写入，退出时删除。
- 健康接口唯一为 `GET /api/v1/health`（无 `/health` 别名），返回 `{serviceStatus:{state,version,uptimeSeconds,setupCompleted,ready,instanceId,apiVersion,port,baseUrl,startedAt}}`。
- 端口策略：#99 实现为 优先 43120 → 备用 43121-43125 → OS 分配空闲；服务只监听 `127.0.0.1`；Host/Origin 白名单随实际端口动态放行。
- 单实例语义：#99 sidecar 层「已有存活实例 → 启动失败（`another live-recorder instance is running (pid=…)`）」，Tauri 壳负责聚焦既有窗口；退出只删本实例锁。
- 冒烟房间：https://live.bilibili.com/27519423（持续开播）；端口占用替身：本地启动监听 43120 的 stub 进程。
- 退出顺序（固定）：停止接收新请求 → 停止调度新任务 → 收束活跃录制/连接 → 关闭 DB → 删除 ready/实例锁（SIGINT/SIGTERM 均走该顺序）。

## 6. BOOT-06 残留 PID / ready / 锁文件

| 项 | 内容 |
|---|---|
| 前置 | 构造三类残留：①PID 不存活（instance.lock 写入 `{instanceId,pid,version,startedAt}` 且 pid 不存在）；②PID 存活但非本实例；③活跃且兼容实例 |
| 步骤 | 1) 启动应用；2) 观察对残留状态的处理 |
| 断言 | 先校验 PID 存活 + `instanceId` 与 health 匹配后才认定旧实例；PID 不存在（过期残留）→ 自动清理后重取锁；已存在且 PID 存活但属于其他实例 → 拒绝不覆盖；活跃且兼容实例被复用聚焦；未知进程不被静默终止 |
| 异常 | 误杀未知进程 = Blocker |
| 自动化 | 集成测试：注入三类残留状态文件 → 断言清理/复用/不误杀（sidecar.test.ts 已覆盖过期清理与拒绝） |

## 8. BOOT-08 录制中关窗 / 退出 / 异常退出

| 项 | 内容 |
|---|---|
| 前置 | 录制中（真机或假流录制中） |
| 步骤 | 1) 关窗（默认最小化到托盘）→ 录制持续；2) 托盘明确退出 → 二次确认 → 服务收束；3) 异常退出（kill -9 / 崩溃）→ 重启 |
| 断言 | 关窗最小化不影响录制（录制持续、不丢录、activeRecordings 不变）；明确退出前二次确认并说明会停止服务；正常退出有收束顺序（停止接收→收束录制→删 ready/锁）；异常退出后重启能恢复（不重复录制、不遗留卡 recording 状态，复用 recoverStaleRecordings 语义） |
| 异常 | 关窗丢录、异常后重复录制、遗留占并发槽 = Blocker |
| 自动化 | 集成测试：录制中关窗替身 + 二次确认替身 + kill -9 后重启恢复断言 |
